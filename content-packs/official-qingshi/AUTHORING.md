# 作者替换说明

## 交接与更新步骤

1. 保留原包副本，在本包上创作。修改运行内容时增加 `manifest.json.version`，例如 `0.1.1` → `0.1.2`。
2. 开发者将本目录放回游戏仓库的 `content-packs/official-qingshi/`，替换对应文件。只交这个目录即可；不需要改网页组件里的对白。
3. 在游戏仓库根目录执行 `npm run content:prepare`。脚本校验 JSON 和引用，将包内图片复制到网页静态目录，重新生成内容锁以及网页可下载的模板 ZIP。
4. 执行 `npm run typecheck:game`、`npm run test:content`，再执行项目已有的构建命令 `npm run build`。构建前也会自动执行内容准备。
5. 用新测试局验收，再按项目的网页发布流程更新。替换文件不等于已经更新线上页面；当前没有游戏内上传内容包功能。

## 编剧：改故事

`outline.md` 是大纲；实际播放的是 `storylets.json`。保持节点 ID 和选项 ID 稳定，修改标题、正文、提示和选择后回应。选项 `effects` 才会改变真实状态，正文写“得到了丹药”不会自动给奖励。

节点由全部条件共同匹配，数组越靠前优先级越高。一次性事件需要一个退出条件：例如要求自定义标记为 false，选项将其设为 true。声明新标记到 `manifest.declaredFlags` 后即可用于条件；不要覆盖引擎的保留事实。完整接口见 `content-api.md`。

大纲中的探索、结算、补偿等规则入口由引擎提供。`presentation.json` 可以替换这些阶段的过场和结果文字，不能改写其实际物品数或时间代价。新命令和新奖励请交给程序员扩展接口与测试。

## 人物：显示名与身份分开

`characters.json` 配置 primary 和 companion。显示名可以改，但 `id` 必须与 `manifest.roles` 相符。玩家身份不出现在这里，禁止将角色位绑定 `PLAYER`。

正文使用 `{{primary.name}}`、`{{companion.name}}` 和 `{{player.name}}`，从本局人物取名，不要反复手写姓名。没有表达式、HTML 执行或任意变量访问。改姓名、性别或外貌时同时检查代词、称呼、图片与 `alt`；姓名占位符不会自动替你改“她／他”。

人物年龄、修为等是新局初值；运行中会被模拟改变。更换人物身份须开新局，不能把旧人的记忆直接移给另一人。初始年龄暂允许 18–70 岁，境界 0–4。

## 美术：换图不改剧情

1. 把 PNG、JPG 或 WebP 放到 `art/images/`，文件名使用英文字母、数字、点、下划线或短横线。
2. 修改 `art/manifest.json` 对应视觉 ID 的 `file`、`url`、`width`、`height`、`alt`、`subject`。`file` 是包内路径，`url` 是网页 `/art/` 下的公开路径。
3. 保持同一视觉 ID 的用途和人物身份一致。若是新用途，新增视觉 ID，再在节点／地点／过场中选择它。场景 ID 必须指向 scene，人物 ID 必须指向 portrait。
4. 执行内容准备，检查手机与桌面裁切。源文件只在包内维护，`public/art/` 是脚本生成的副本，不要只改副本。

推荐场景接近 16:9，人物竖图接近 2:3。当前三张图是首版生成的占位美术，场景为像素风，人物立绘为细绘风，后续可统一风格。新增人物图集与小传由 `npc-presentation.json` 独立提供，周安和其余 NPC 已有可用面孔。图片来源与交付约束见 `art/README.md`。

## 存档与边界

内容准备按运行 JSON 和图片计算 SHA-256，并将版本与摘要一起写入存档锁。即使忘记增加版本号，内容变化仍会被检测出来。原故事包采用严格匹配：其中的文字或三张原图改变也会使旧局不兼容。新增 NPC 展示补充包有独立校验，不进入这个锁。后续可由程序员实现更细的兼容策略。

更新前先从旧网页导出存档。不能用手改 `packLock` 的方式强行导入；需要匹配的旧网页内容继续旧局，或建立经过测试的迁移。报错不会自动清除旧档；明确新建或导入另一个存档才会替换当前进度。

当前只有一个构建时官方包。新增地点 ID、增减剧情角色位、变更物品类型、脚本执行、多包共存、运行时 ZIP 安装与自动迁移都需要开发支持。只调整展示、组合现有条件／效果和换图时应不需要修改引擎或页面组件。

## 补充 NPC 资料与图集

- 文案编辑 `npc-presentation.json` 的 `fixed.primary`、`fixed.companion` 与 `backgrounds`。每条包含 `origin`、`background`、`interest`、`wish`。这是身世设定，不是已经发生的事件；共同经历只能来自引擎事件记录。
- 美术在 `art/images/npc-*.png` 替换六张图集；保持 PNG、正方形 3 × 3 等分、无沟槽，文件尺寸须与 JSON 一致。当前为 1254 × 1254，每格 418 × 418。
- `atlases[].sex` 决定人物性别，`slots[].index` 按行从 0 到 8，`age` 是视觉参考年龄；不要删改现有格位身份，以免旧人物换脸。`description` 是交接用形象说明。
- 固定角色在 `fixed.*.portrait` 指定静态路径和格位；`slot:null` 表示整张图。替换主要人物身份时须同步原人物初值与故事代词，另行处理存档兼容。
- 调整纯展示素材时更新 `npc-presentation.json.version`，执行 `content:prepare` 生成独立摘要；无须更改原故事 `manifest.version`，也不可手改原内容锁。
- 开发者若要扩展图池，可添加完整 3 × 3 图集，校验与分配会自动使用；增加图池可能改变分配次序，应视为外观升级并复测旧人物。
