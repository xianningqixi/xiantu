# 青石人间 · 故事与配图模板

这份包就是《仙途》网页当前读取的首章内容。用于交给编剧、美术和开发者继续替换，不是独立运行的游戏，也不是上传即用的 Mod。

玩家自行创建姓名、性别、外貌、资质与伴生法宝。林晚是 `primary` 角色位的示例 NPC；周安是 `companion` 同行 NPC。两人都不是预设男女主，没有预设恋爱关系。

## 从哪里开始

1. 阅读 `outline.md`，了解故事动机与两条后果分支。
2. 编剧修改 `storylets.json` 和 `presentation.json`；美术替换 `art/images/` 与 `art/manifest.json`。
3. 按 `AUTHORING.md` 交由开发者更新网页，完成 `acceptance.md` 中的检查。

| 文件 | 用途 | 是否影响网页运行 |
| --- | --- | --- |
| outline.md | 人工阅读的故事大纲、节点意图 | 仅供创作沟通 |
| manifest.json | 包版本、角色位、入口、进度标记 | 是 |
| storylets.json | 8 个实际故事节点、触发条件、选项与回应 | 是 |
| locations.json | 4 个现有地点的文字与视觉引用 | 是 |
| characters.json | 2 位示例 NPC 的初始资料 | 是，仅新局初始化 |
| presentation.json | 开场、战后过场、履约／违约结果文案 | 是 |
| art/manifest.json | 视觉 ID → 实际文件、路径、尺寸与替代文字 | 是 |
| art/images/ | 3 张故事原图与 6 张 NPC 图集 | 是 |
| npc-presentation.json | 全体 NPC 小传模板、固定角色资料、图集年龄与格位 | 是，仅展示 |
| npc-presentation-integrity.json | 独立的 NPC 展示校验值 | 自动生成，不进入存档锁 |
| integrity.json | 自动生成的内容锁与图片校验值 | 是，请勿手改 |
| AUTHORING.md / content-api.md / acceptance.md | 替换流程、接口和验收 | 文档 |

多幕可以复用一张图。大纲、事件和图片分别维护，通过稳定 ID 关联。内容包只描述叙事和已有规则的组合；时间、战斗、物品、关系计算与存档仍由游戏引擎执行。

## 第一版范围

本轮支持构建时装入一个官方内容包。支持替换文字、NPC 初始资料、现有地点展示、插图、条件和已实现选项效果。尚不支持游戏内上传 ZIP、多包安装管理、旧存档自动迁移、自由脚本或 AI 自动执行规则。

存档严格锁定内容版本与内容摘要。替换运行内容会产生新锁，旧局会提示不兼容并保留原数据；请先在旧网页导出存档。继续旧局需要匹配的旧内容版本，备份 JSON 本身不包含图片和内容包。

## 新增人物展示补充包

`npc-presentation.json` 单独维护出身、小传、偏好、心愿和立绘。林晚与周安有专属资料，其余人物依外貌 Seed 固定选择背景模板；年龄、境界、所在地、性情、目标、关系和经历仍读本局真实状态。

六张图集共 54 个成年修士形象，男女各 27 个。周安固定用男性第一图集的第 0 格，林晚保留原图。其余人物按性别、初始年龄及稳定次序分配；默认 Seed 12345 的 40 人不重复，超过图池容量会复用。每张图集 3 × 3，页面只显示对应格位。不是游戏运行时生图。

仅修改该补充包及其六张图集不会改变原存档锁。补充包有自己的版本和校验清单；不得往其中塞入奖励、时间、关系数值或规则效果。旧 `characters.json` 中周安的 portraitId:null 是原版初值元数据，目前由本补充包提供展示图片。替换规则与人物身份仍按原版本兼容要求办理。
