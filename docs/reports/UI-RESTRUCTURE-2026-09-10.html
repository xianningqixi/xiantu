仙途 · 青石人间 · UI 操作重构方案

把五个页签、三层地图、四个入口，收成一个主画面和一个按钮

这不是又一轮 UI 打磨。上一轮 74 项评审已经把每个面板单独修得很规整了，但玩家的感受是"元素很多、很散、不知道该干嘛、干了也没感觉"。问题在结构和反馈密度，不在单个控件。

一句话结论

现在的游戏把"修仙"做成了一个资料管理系统：玩家在页签、地图、地点、弹窗之间导航，去找那个能推进时间的按钮；按下之后，得到的是一根填满的进度条和一句散文。市面上能让人玩下去的修仙游戏，不管是放置类、文字类还是开放世界类，都做对了同一件事：主画面永远是角色和修为，屏幕上永远有一个明确的"下一步"按钮，每次按下都在一两秒内给出可见的数字和事件反馈。

方案分四层，前两层纯 UI、不动规则引擎，一周内能落：

  1. 信息架构：删掉"地图中间页"和独立的"修行"页签，把角色状态、当前场景、事件流和主行动合成一个"道场"主画面；底部固定 4 个入口。
  2. 目标即按钮：现在"眼下之事"是侧栏里一段文字加"去看看"，改成主画面正中那个唯一的大按钮就是目标本身。
  3. 反馈密度：修炼、等候、杂务不再"跳日数"，而是每一天在事件流里滚一行，数字飘字，NPC 自主人生的事件实时进流，小境界晋升有仪式。
  4. 渐进解锁：凡人期只看到 2 个按钮，地图、宗门、同行、道侣随境界逐一亮起。规则不变，只控制显示。

再往下是数值节奏：26 个游戏日封顶、资质只差 ±4／天、整局只有一场战斗，这些 UI 救不了，单列在配套数值建议。

实际玩下来看到什么

我用生产构建走了一遍新手前十分钟：创角、进坊市、与林晚见礼、领功法、去修行页。以下是截图里最能说明问题的几处。

第一屏

创角结束后落在"山河辽阔，随心而行"的地图中间页：三张地点卡片各带 3 张头像和"44 人 / 29 人 / 33 人"，左侧栏 5 个区块，顶部 5 个页签，右上地图按钮，底部"主线足迹"折叠。首屏可点击元素 20 个以上，其中没有一个是动词。

玩家第一反应是"我该点哪个"。同类游戏第一屏只回答一件事：你是谁、现在按哪里。

同一件事四个入口

"修炼"这件事可以从：侧栏"眼下之事 → 去看看"、顶部"修行"页签、地点底部行动条"寻找入门功法"、以及剧情选项进入。它们指向的还不完全是同一个地方（页签是面板，行动条是命令）。

入口越多，玩家越不确定哪个才是"正确的"。这是"分散"感的直接来源。

三层导航

做一次修炼要经过：页签（游历）→ 地图中间页 → 进入地点 → 底部行动条 → 跳到修行页签 → 选推进方式下拉 → 选日数单选 → 开始闭关。八步。"一念逍遥"是一步，"想不想修真"是两步。

修炼的反馈

按下"开始闭关"后，是一个进度条从 0/7 走到 7/7，旁边一句"正在修炼，世界也在继续"。结束后修为从 0 变成 20。wait 命令的回执是"坊市依旧人来人往"，产出为零（commands.ts:308-331）。

这七天里世界确实发生了事（NPC 在结识、择宗、赶路），但全部被攒进"闭关摘要"里事后一次性给，玩家在推进的当下什么也看不到。

静默的成长

炼气一层到三层是自动晋升（cultivation.ts:48-53），没有任何仪式。五段成长里三段玩家根本不会注意到自己升了。关系数值默认隐藏（balance.json:588），"相伴一日"后只有一句叙述。

文案

"山河辽阔，随心而行""道途 · 一呼一吸""有人萍水相逢，有人会成为你这一世的牵挂"。写得好，但它们出现在本该放动词的位置上。所有页面标题都是意境句，没有一个告诉玩家这页是干什么的。

不好玩的五个根因

把截图观察和数值梳理合在一起，归成五条。前三条是 UI 结构能解决的，后两条需要动数值。

1. 没有"主画面"，只有一堆平级的面板

五个页签平级，游历页里又套地图和地点两层，角色状态被放在侧栏当装饰。玩家没有一个"回家"的地方。修仙游戏的主画面从来都是角色本人加修为条，因为那就是玩家在乎的东西。

2. 目标是文字，不是按钮

presentation.ts 里的 objective() 其实算得很好：战斗、战利品、长行动、剧情、约定、突破、主线都排了优先级。但它的输出只是侧栏一段文字和一个"去看看"，点了之后还要在目标页面里再找一次真正的按钮。算出来的目标应该直接变成主按钮，而不是变成一段介绍。

3. 反馈被延迟、聚合、隐藏

时间推进期间无实时反馈；NPC 事件攒到闭关摘要；小境界无仪式；关系数值隐藏；等候零产出；杂务恒定 +6 无变化。每次操作和"我变强了 / 世界变了"之间隔着好几步。

4. 成长阶梯又短又平（数值）

凡人到筑基约 26 个游戏日、20 到 30 次点击就封顶（foundationAdvancementEnabled:false）。资质 1 和 100 的差别是每天 ±4 修为（aptitudeGainDivisor:25），创角时"重掷灵根"这个仪式感十足的操作，实际上几乎不影响体验。溢出修为直接丢弃。

5. 系统之间是孤岛（数值）

战斗整局只有一场脚本遭遇且非致命（randomRoadEncounterBp:0）；灵石除了买一颗突破丹（30 灵石 = 5 天杂务）没有别的去处，出售关闭、无日常开销；宗门只是把同一条修为磨快一点，不改变剧情、战斗或关系。100 个有立绘、有小传、会自主生活的 NPC 是这个项目最贵的资产，但玩家和他们的交互被埋在"资料弹窗 → 关系页签 → 展开交往操作"三层之下。

同类游戏怎么做

看三种做法差异很大的产品，找它们的共同点。

提炼出六条原则，后面的方案全部对着这六条来：

主画面 = 角色 + 修为 + 一个主按钮其他一切都是从主画面出去再回来的抽屉，不是平级页面。
目标就是按钮任何时候屏幕上有且只有一个最亮的按钮，按它一定是对的。
时间流逝必须可见推进一天就滚一行事件，不允许"进度条填满再一次性结算"。
数字要动给玩家看修为、灵石、好感的每一次变化都飘字或跳动，隐藏数值只在极少数叙事场合成立。
渐进解锁，不是一次性摊开新手看到 2 个按钮，每升一个境界多亮一个系统，并且要"叮"一声告诉他。
三层循环短循环 30 秒内有反馈（一天修炼），中循环几分钟一次高光（晋升/突破/结识），长循环几十分钟一章（主线/入宗/道侣）。

方案二：核心循环与反馈

目标：按一下，一两秒内看到三样东西同时发生：日期跳、数字飘、事件流多一行。

修炼从"配置 → 闭关 → 结算"变成"按一天看一天"

  • 主按钮默认修炼 1 日；旁边一个"修炼 7 日"和长按/展开出的"修至圆满 / 遇事暂停"。删掉推进方式下拉和 1/3/7/30 单选。
  • 多日修炼时，Worker 已经是逐日保存并发轻量进度（README 写明），UI 直接把每一日的进度当作事件流的一行渲染出来，再配 +8 的飘字。玩家看到的是七行滚过去，而不是一根进度条填满。推进速度控制在每日 300–500 毫秒，可点击加速。
  • 推进途中触发的 NPC 事件（结识、入宗、抵达、突破）实时插入事件流并高亮，而不是攒到摘要里。stopWhen: importantEvent 已经存在，只需把"重要事件"同时推给事件流。
  • 修为满时主按钮自动变成"尝试引气入体"，并且修为条闪一下。这个判断 objective() 已经有了。

晋升与突破要有仪式

  • 炼气一层到三层的自动晋升，规则不改，但 UI 在检测到 realm 变化时弹一次全屏一秒的境界卡："炼气二层 · 每日修为 +10 → +12"。中循环的高光时刻不能被吞掉。
  • 突破改成弹窗仪式：成功率大字、可勾选丹药和护法、一个"凝神"按钮；按下后有 1–2 秒的气机汇聚动画再出结果。现在的 breakthrough-card 内容都对，只是被埋在修行页下半截。

其他动作的反馈

  • 等候改名"闲逛 / 停留"，回执从"坊市依旧人来人往"改为随机一条当地小见闻，并且事件流里出现当日 NPC 动态。这条需要规则层加一个小随机文案池（不影响随机序列的话可以纯 UI 从事件里取）。
  • 杂务：+6 灵石飘字，回执从 3–5 条文案里轮换。
  • 相伴 / 见礼：好感和信任改为可见的阶段条（陌生 → 相识 → 朋友 → 挚友），每次交互条会涨一格。这点 U-14 评审已经做了"下一阶段缺口"，往前一步做成条。
  • 所有写世界的命令，回执都从顶部横条改为事件流最新一行 + 飘字，顶部那条"已创建测试者的这一世·第 1 日 / 已保存"横条删除，保存状态移到右上角一个小勾。

方案三：目标即按钮

objective() 的优先级链保留，输出改成三段式：

战斗中青芒剑诀 / 普攻battle 命令，战斗面板就在场景位置
剧情选项待选选项本身（1–3 个并列）choose / chooseMain
修为圆满尝试突破 · 65%打开突破仪式弹窗

方案四：渐进解锁

规则层什么都能做，UI 层按境界控制显示。每次解锁弹一张卡片"新的去处已开启"，并在对应入口上加一个点。

秘境和宗门的具体境界门槛可以再商量，原则是每升一级至少亮一个新东西，让"升级"这件事在 UI 上有实际含义，弥补现在小境界静默的问题。

方案五：各页面处理

游历（原地图弹窗）

现有 AtlasDialog 里的大地图是全项目最清晰的一个界面：位置、路径、天数、启程按钮都在一屏。直接升级为底部入口，去掉"地图中间页"里那三张带头像的地点卡。地点上的人物数量改成"已结识 2 人在此"而不是"44 人"，陌生人数量对玩家没有意义。

人物（原故人）

首屏三段：同行之人（0–2 人）、已结识（按关系阶段排序，带阶段条）、此地在场（陌生人，只显示头像和境界，点头像见礼）。搜索、筛选、分页折叠进"全部人物"二级页。人物资料弹窗保留四页签，但"关系"页的交往动作（相伴、结侣、共修）提到弹窗底部固定栏，不再要展开。

修行（并入道场）

独立页签取消。灵石辅助、停止条件、护法条件这些设置进"修炼设置"抽屉；突破进仪式弹窗；"筑基已成"的终点卡改成道场事件流里的一条大事件。

行囊

基本保留。购买动作同时挂在道场的"坊市"次级动作下，玩家不用为买一颗丹专门切页。

创角

结构没问题，但它现在把 AI 立绘、胸围、种子、内容包全部摊在第一屏，新手看到的门槛比游戏本身还高。建议：默认只显示姓名、性别、四选一外貌、法宝三选一、"踏入仙途"；身高胸围种子内容包收进"更多设定"折叠。AI 立绘按钮保留但降为次级。

落地路线

三期，前一期不改规则引擎，可以独立验收。文件引用对应当前仓库。

第一期 · 主画面成形

纯 UI · 约 1 周
  • 新建 dojo.tsx 主画面：顶部状态条 + 场景/剧情区 + 事件流 + 主按钮 + 次级动作；game.tsx 的 NAV 改为 道场/游历/人物/行囊。
  • objective() 返回值增加 command 字段，主按钮直接执行；删除侧栏目标卡。
  • 新建 event-feed.tsx：数据来自 world.events、knownNpcUpdates()、game.lastResult、长行动逐日进度；飘字组件挂在状态条数字上。
  • 删除 world-map.tsx 中间页，AtlasDialog 升级为游历页；journey-tab.tsx 的场景/剧情/在场人物拆成道场子组件。
  • CultivationPanel 拆为主按钮、修炼设置抽屉、突破仪式弹窗；RetreatSummary 改为事件流中一条可展开汇总。
  • 人物页首屏改三段式；创角页折叠"更多设定"；标题与按钮文案动词化。

涉及：components/game/game.tsx、journey-tab.tsx、world-map.tsx、panels.tsx、character-sidebar.tsx、retreat-summary.tsx、creation.tsx；lib/game/presentation.ts、journey-actions.ts；app/globals.css

第二期 · 反馈与解锁

UI 为主，少量规则 · 1–2 周
  • 境界变化检测 → 晋升卡片；突破仪式动画。
  • 渐进解锁表落地为 ui-presentation.json 里的配置，配套解锁提示卡。
  • 长行动逐日推进的节奏控制（300–500 ms/日，可加速），重要 NPC 事件实时插流并高亮。
  • 关系阶段条；等候改"停留"并从当日事件中取一条见闻（若需要新随机文案池则进规则层）。
  • 杂务、见礼等回执文案池。

涉及：content-packs/official-qingshi/ui-presentation.json、lib/game/use-game.ts（进度事件）、lib/game/journey-presentation.ts、lib/game/commands.ts（回执文案）

第三期 · 数值节奏

改规则 · 需回归测试
  • 按上表调整 balance.json：资质权重、境界表扩展、阈值曲线、溢出结转。
  • 城间随机遭遇（非致命）接入现有战斗；灵石长期去处。
  • 跑 test:game、test:stress、typecheck:game，旧档迁移按现有规则版本机制处理。

边界守住的地方：三期都不改"所有世界写入经 Worker、查看不推进时间、重绘不改随机"这些硬约束。第一期只是把已有命令换了个更近的入口，把已有事件换了个更早的呈现时机。

验收标准

不用问卷，用新手自己走一遍就能量出来的数字：

≤ 3 步从任意状态到"开始修炼"的点击数（现在 8 步）
≤ 7 个道场首屏可点击元素（现在 20+）
≤ 30 秒任意两次可见反馈之间的最长间隔
1 个屏幕上同时最亮的按钮数
≤ 3 分钟新手从创角到第一次修为条填满
每升一级至少一个新入口亮起并有提示

最后一句：这个项目的资产（129 张立绘、四卷主线、NPC 自主人生、三宗）是远超原型级别的。现在的问题是玩家碰不到它们，因为界面让他们在找按钮。把按钮送到手上，资产自己会说话。
