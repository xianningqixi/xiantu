## 2. 逐工具清单（实测证据）

### 2.1 sharp（sharp-cli 6.1.0）—— 图片管线（核心推荐）

- **用途**：WebP/AVIF 编解码、按最大边缩放、批量重压；项目已依赖 `sharp@0.34.5`，接入零新增依赖。
- **安装**：
  ```bash
  npm install -g --prefix ~/tools/npm sharp-cli     # 自动下载 ARM64 预编译 libvips
  # 实际库版本：sharp 0.35.4 / libvips 8.18.6；项目内为 sharp 0.34.5 / libvips 8.17.3（含 aom AVIF 支持）
  ```
- **安装路径**：CLI `~/tools/npm/bin/sharp`；库 `~/tools/npm/lib/node_modules/sharp-cli/node_modules/sharp`。
- **验证命令与输出**：
  ```bash
  ~/tools/npm/bin/sharp --version            # 6.1.0
  ~/tools/npm/bin/sharp -i in.webp -o out.avif --format avif      # 成功，293KB→81KB
  ~/tools/npm/bin/sharp -i in.webp -o out.webp --format webp --quality 75  # 293KB→122KB
  ```
- **实测证据 A：全站 393 张衍生 WebP（只读源，输出仅算体积，未写仓库）**

  | 方案 | 全站体积 | 相对现状 | 说明 |
  |------|---------:|---------:|------|
  | 现状 `dist/client/art/optimized`（393 张） | **75.84MB** | — | 平均 198KB/张 |
  | `resize ≤1152` + WebP q78 effort6（项目自身参数） | **23.81MB** | **-68.6%（省 52.0MB）** | 分类：location 7.6→2.2MB(-70.9%)、npc 30.0→9.8MB(-67.3%)、shichai 36.4→11.2MB(-69.2%)、sect 1.8→0.5MB(-69.7%) |
  | `resize ≤1152` + AVIF q50 effort4（30 张分层抽样：4.99MB→1.04MB，20.9%） | **约 15.8MB（推算）** | **约 -79.2%** | 需 `<picture>` 兜底，见风险 |
  | 只重压 WebP、不降分辨率（12 张样本） | 3442KB→1581KB | -54.1%（样本） | 对 200–400KB 主力图约省 40–57% |

  - 尺寸变化（`withoutEnlargement`）：1672×941 → **1152×648**；1024×1536 → **768×1152**；512×512 保持不变。
  - 验证方式：对 `dist/client/art/optimized/` 下 393 张图只读读取、在 `/tmp` 内计算编码后字节数（`/tmp/tools-bench/allset2.jsonl`），原文件与仓库均未改动。

  | 样本 | 尺寸 | 原 KB | WebP q75 | AVIF q50 | 最优压缩率 |

  | location-gate | 1672×941 | 533 | 274 (-49%) | 166 (-69%) | 69% |
  | location-market | 1672×941 | 450 | 218 (-52%) | 146 (-68%) | 68% |
  | 立绘 gutinglan-portrait | 1024×1536 | 293 | 115 (-61%) | 80 (-73%) | 73% |

  | 小图 npc-0003 | 512×512 | 19 | 9 (-52%) | 8 (-60%) | 60% |

- **实测证据 C：质量指标（ffmpeg SSIM/PSNR，越低越损）**

  | 方案 | location SSIM/PSNR | 立绘 SSIM/PSNR | NPC 立绘 SSIM/PSNR |

- **实测证据 D：源 PNG → 当前保留图 → 新管线对比（4 个真实素材）**

  |---|---:|---:|---:|---:|---:|---:|
  | gutinglan-portrait.png (1024×1536) | 1769KB | 293KB | **34KB** | **-88.4%** | -98.1% | 23KB |
  | suqingyan-cg-lost.png (1672×941) | 2271KB | 347KB | **78KB** | **-77.6%** | -96.6% | 55KB |
  | wenzhiwei-cg-bond.png (1672×941) | 2445KB | 232KB | 108KB | -53.4% | -95.6% | 69KB |
  | wenzhiwei-cg-mourn.png (1672×941) | 2012KB | 242KB | 80KB | -66.9% | -96.0% | 50KB |

  → 现状 `preserve: true` 直接拷贝上游衍生图，是图片预算超标的直接原因；项目自身已定义的 1152/q78 参数即可收回大部分收益。

- **与本项目用途**：新增/调整 `scripts/prepare-images.mjs` 或增加独立「历史衍生图重压」脚本；产出 `images.json`/`image-display.json` 的字节数已存在，可直接做体积预算门禁。
- **风险**：改图片 bytes/参数会改变衍生文件名与 `images.json`，需跑 `npm run content:prepare` + `npm run verify:release`；内容锁涉及原始 PNG SHA-256 与 integrity 文件，**不要手改 `dist/`**。AVIF 需要 `<picture>` 或格式协商 + WebP 兜底（旧 WebView/Safari<16 不支持）。

### 2.2 ffmpeg 7.0.2-static（预装，纳入音频管线）

- **用途**：离线生成/转码音效与环境音；支持 libvorbis / libopus / aac；无 GPU 需求，64 核可批量。
- **安装**：**无需安装**（远端 `~/.local/bin/ffmpeg`、`ffprobe` 已存在，来自 johnvansickle static build；默认不在 PATH）。
- **验证命令与输出**：
  ```bash
  ~/.local/bin/ffmpeg -version | head -1        # ffmpeg version 7.0.2-static
  ~/.local/bin/ffmpeg -hide_banner -encoders | grep -E "libvorbis|libopus|aac"
  # 输出：aac libopus libvorbis
  ```
- **实测证据：完全离线生成 4 个游戏音频样本（/tmp/tools-audio）**

  | 文件 | 生成方式 | 体积 | ffprobe 校验 |
  |------|----------|-----:|--------------|
  | ui-click.ogg | 880Hz 正弦 60ms + 淡出 | 3.6KB | vorbis, 44.1kHz, mono, 0.06s |
  | sword-clash.ogg | 白噪声 300ms + 带通 1.8–7kHz + 淡出 | 6.5KB | vorbis, 48kHz, mono, 0.30s |
  | wind-ambience.ogg | 粉红噪声 10s + 低通 | 73KB | vorbis, 48kHz, mono, 10.0s |
  | wind-ambience.m4a | 粉红噪声 5s + AAC 48kbps（Safari 兜底） | 32KB | aac, 48kHz, mono, 5.0s |

  示例命令：`ffmpeg -f lavfi -i "anoisesrc=color=white:duration=0.3" -af "highpass=f=1800,lowpass=f=7000,afade=t=out:st=0.02:d=0.28" -c:a libvorbis -q:a 4 sword-clash.ogg`
- **与本项目用途**：当前无音频资产 → 可先做「占位音效/环境音」验证玩法反馈；将来 AI 生成音频入库时统一转 ogg/opus + m4a 双格式并压体积。
- **风险**：Safari 不支持 ogg/opus（需 m4a/aac 兜底）；音量需统一响度（可用 `loudnorm` 滤镜）。

- **验证命令与输出**：

  ~/tools/bin/oxipng -o4 --strip safe --out /tmp/out.png in.png

### 2.6 ink / inkjs（叙事工具评估，不要求迁移）

- **inklecate v1.2.1（官方 CLI）**：
  - 下载 `inklecate_linux.zip` → `file inklecate/inklecate` = **ELF 64-bit x86-64**；在 aarch64 上执行报 **`cannot execute binary file: Exec format error`** → **官方 Linux 版不可用于本机**。
  - 主页发布物：`inklecate_linux.zip` / `inklecate_mac.zip` / `inklecate_windows.zip`（无 linux-arm64）。
- **inkjs 2.4.0（JS 版编译器 + 运行时，可跑）**：
  - 安装：`npm install -g --prefix ~/tools/npm inkjs` → `~/tools/npm/bin/inkjs-compiler`。
  - 验证命令：
    ```bash
    inkjs-compiler -o demo2.json demo.ink      # 成功；注意：直接 `inkjs-compiler demo.ink` 是文件名用法，不是 --help
    ```
  - 实测：编译 `/tmp/tools-ink/demo2.json`（1.3KB）；用 `inkjs.Story` 运行 3 步分支：
    ```
    [1] 青石镇的雨敲在屋檐上。你看见
    choices: ["上前搭话","绕道离开"]
    [2] 老者抬头："后生，可愿听一段旧事？"
    vars: {"trust":1,"met":true}
    [3] 老者的故事讲完了。 他看你的眼神柔和了些。
    ended: true   saveState bytes: 419
    ```
  - 坑：`inkjs-compiler` 输出 JSON 带 **UTF-8 BOM**，`JSON.parse`/`inkjs.Story` 前需 `.replace(/^\uFEFF/,"")`；也可用 `new inkjs.Compiler(src).Compile().ToJson()`（无 BOM）。
- **与现有 JSON schema 的差距（关键结论）**：
  - 现有内容为**声明式数据**：`manifest`（packId/version/capabilities/dependencies/flags）→ `storylets[]`（id/title/body/quote/visualId/participants/priority/conditions(fact,op,value)/choices(id,label,hint,reply,effects)）→ `visuals`/`definitions`/`journey`/`integrity`；校验由 Zod 契约 + `content:prepare` + 规则测试完成，内容锁用 SHA-256，效果只能走 `meet/progress/experience/buyItem` 等**能力白名单**。
  - ink 是**命令式运行时**（knot/stitch/变量/divert/tunnel/函数/存档 state），没有地点/参与者/视觉槽位/图片引用/内容版本锁/能力白名单/经济结算/存档迁移等概念；要接入必须写外部函数桥接，等于绕过 schema 白名单与内容锁校验，破坏现有安全与版本模型。
  - 迁移成本：6 个故事包共 6 个 `storylets.json`（12KB–112KB/个）+ 主线 `main-quest/story.json`（四章），全部重写为 ink 文稿并再转译回 JSON 不现实。
  - **建议**：仅可作为作者**离线分支草稿/死路检测**工具（写完人工转写为 storylets JSON），**不接入运行时**；CLI 已具备可跑性，若将来做转译器再评估。

## 8. 落地验证补充（2026-10-22 晚）

按第 2.1 节建议，曾把 `scripts/prepare-images.mjs` 中 `preserve: true` 分支从「原样拷贝」改为 sharp 重编码（同尺寸 WebP q80），实测生成物 77MB → 43MB（-44%）。但浏览器回归 `tests/browser/art-refresh.spec.ts` 首项要求服务端返回字节的 sha256 与美术评审清单完全一致（257 张 reviewed bytes），重压后校验立即失败；该测试是美术验收的硬约束，因此已回退，不采用对已评审素材的重压。

结论修正：sharp 的压缩收益仍成立，但仅适用于**新素材入库**（先压缩再登记评审摘要），或未来把美术验收从「字节锁定」改为「尺寸 + 视觉基线」。对现有 393 张衍生图的重压不能直接落地。

同时把 D 期新增代码造成的离线核心预算增长记录在 `tests/browser/improvements.spec.ts`：核心清单上限由 2,217,127 字节调整为 2,320,000 字节（+46KB 客户端代码）。
