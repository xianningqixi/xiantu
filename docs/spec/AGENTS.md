# Codex 项目执行规范

本目录是修仙 Web 图文游戏的执行规格包。当前任务是按下列文档逐项实施；本文件不是技能文件，不执行技能安装流程。

## 依据与优先级

1. 用户最新明确要求。
2. GDD 中的“已确认约束”。
3. GDD 的原型默认及 prototype-balance.json。
4. TDD、COMMANDS、UX_CONTENT 与契约文件。
5. 当前 Task 和 Acceptance 条目。

发现同一含义在文件中冲突时，先记录冲突并优先保留用户硬约束。可直接修复字段拼写与显然的文档不一致；改变已确认玩法需向用户说明具体影响。数值原型默认可以实现，不需要逐个重新问许可。

## 开始一个任务

- 读取 README、对应 Task、相关设计与验收条目，确认依赖已完成。
- 检查目标仓库已有规范、工作区修改和运行环境，保留用户改动。
- 先给出本任务产物与验证范围，然后实施；不扩大到后续里程碑。
- 以独立任务分支或适当隔离工作区工作。独立接口和审查可并行，同一核心文件避免并发修改。

## 实现边界

- 使用原生 Web 图文页面。core 纯 TypeScript，玩家与 NPC 共用规则；UI 不写世界实体。
- 所有时间和随机经项目服务获得，不在组件render、Effect或图片回调里推进游戏。
- 每条命令校验 payload、资格、ID、revision 和去重记录；事务完整成功后才确认已完成。
- 图片引用、文字、事件和数值必须对应同一已提交状态。历史可回看，历史选项不可再执行。
- 突破失败永不直接致死；真正死亡停止行动并保留身份与记忆。复杂模式按死亡事实结束本局。
- AI仅提出白名单提议，不能直接设置资源、境界或关系；接口凭证只放服务端。
- 预制图片按assetId与角色绑定。planned素材使用清楚占位，不声称正式资源已完成。
- 内容和用户／模型文字按文本渲染，禁止eval、任意HTML、任意脚本或任意上游代理地址。
- 修改保存结构或内容语义时处理版本；不以清空旧档“解决”迁移和校验错误。

## 验证与结束

按任务关联AC执行有效测试。规则、存储与浏览器测试各自报告；未执行项目保持not_run，不用单纯构建成功代替全部验证。

对低影响文案和样式使用合适人工检查；涉及存档、随机、死亡、资源和AI写入时补相应回归。验证足以解决当前风险后停止可选扩测。

任务结束交付：修改目的与实际结果、关键文件、运行／复现步骤、验收证据、剩余问题和下一依赖。若本机没有目标浏览器或凭证，完成能执行的部分并明确未验证项，不虚构通过。

本包 tools/verify_pack.py 只检查规格和样例的一致性。它通过不等于游戏逻辑、100NPC模拟或移动端已通过；不得将其当成AC软件验收结果。
