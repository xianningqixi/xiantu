# 交给 Codex 的第一条任务

下面正文可直接复制到已经打开目标项目目录的 Codex。首次只启动 M0-01；在验收成功后按依赖接续，不要求用户重新解释整个游戏。

---

请依据本目录的修仙 Web 图文游戏执行规格包开始开发。

另读 docs/CONTENT_PACKS.md 的内容协作补充，保留大纲、可执行剧情、图片资源和运行存档之间的边界。CP-01—CP-03 是原34项任务之外的新增任务，按其门槛纳入后续开发；第一条官方故事也必须通过同一内容接口接入。

先读 AGENTS.md、docs/GDD.md、docs/TDD.md、docs/COMMANDS.md、docs/UX_CONTENT.md、docs/TASKS.md 和 docs/ACCEPTANCE.md。prototype-balance.json 是允许直接采用的原型默认，不代表正式产品数值；用户硬约束必须保留。

本次执行 M0-01。先检查当前目录是否已有仓库、框架和用户修改：已有项目时在其边界内集成；空目录时初始化 React + TypeScript + Vite 项目和 Git。确定兼容的实际依赖版本并提交锁文件，配置运行、构建、类型检查、纯规则测试和浏览器测试入口。严格按Task写明的关联AC与证据交付，不用“计划通过”代替实际执行。

建立后续所需的 core/application/infrastructure/worker/ui/content 职责边界，但不要顺便实现后续全部游戏模块。保留本包内容在项目的 docs、contracts 和 content-spec 目录，避免被脚手架覆盖。真实 src/content 接入在对应里程碑中完成。

如果缺少工具或测试浏览器，先完成当前获授权且可验证的工作，并报告精确缺口。普通技术细节自行处理；确实影响已确认规则时提交具体冲突与方案。不要部署、申请外部账号或配置用户没有提供的密钥。

完成后报告：实际实现、运行步骤、AC结果、证据位置、未验证项和下一项可执行任务。达到 M0-01 验收后，在当前用户授权范围内按Task依赖继续，保持每个任务可单独审查。

---

接续顺序以 TASKS 的依赖为准。M0-02 是三幕图文夹具；它只是验证“看图—阅读—选择”的节奏。M5 才把同一界面接到真实事件与世界，不把夹具冒充可玩的完整游戏。
