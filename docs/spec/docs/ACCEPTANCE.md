# 验收规格与证据要求

版本：V0.1.1-Web。**本文件定义未来验收，AC-001—AC-069 全部为 `not_run`，没有任何一项已通过。**对应开发任务见 `TASKS.md`。

## 1. 怎么判定完成

**验证类型：**A＝自动行为测试；B＝真实浏览器自动化／集成；M＝人工操作；A+B 等表示两者均需覆盖。浏览器模拟环境不能替代 IndexedDB 与 Service Worker 的真实浏览器验证；桌面手机视口不能冒充真实 iPhone。

**门槛：**P0＝正确性／可恢复性硬门槛，任何失败阻止对应里程碑完成。P1＝界面、体验或测量门槛，需实际记录、修复阻断使用的问题；未达观察目标可保留带原因的缺陷，不得改写为通过。任务所有引用 AC 达到本行门槛才标记完成，`not_run` 不是通过。

**结果枚举：**`not_run / passed / failed / blocked`。缺测试设备、API 配置或试玩参与者记 `blocked`，注明剩余步骤。所有测试首先使用固定种子、固定时钟和 mock AI；真实供应方烟测单独报告，不将某次真实模型措辞当作稳定断言。

每个结果必须标注：实现 commit 或构建指纹、实际命令与退出码、工具及浏览器版本、测试 Seed、规则／生成器／内容／存档版本、实际与预期、失败重放步骤。UI 证据加视口或设备信息。只展示构建成功不能证明存档、跨标签、战斗、世界模拟或离线成功。

## 2. 通用夹具与比较范围

| 夹具／约定 | 用途与边界 |
| --- | --- |
| `minimal-save` | M0 只包含最小规则状态、revision、RNG、事件、会话和命令记录；不要求先实现角色或整个 WorldState。 |
| `creation-draft` | M1 保存 CreationDraft 与 PlayerProfile；尚未生成可游玩的世界。M2 的 FinalizeCreateRun 才建立完整世界。 |
| `world-12345` | 使用 Seed 12345 与锁定生成相关版本的初始世界。正式默认 40 NPC；测试生成器允许显式指定 100 NPC。 |
| 长模拟 Seed 集 | 至少使用 `1、42、12345、20260906、987654321` 五个固定合法 Seed，每个 100 NPC × 3650 游戏日；新发现缺陷的 Seed 加入回归集。 |
| `story-common-start` | 同一故事前置存档，用于履约、违约、没有凝元草掉落、NPC 离队等分支；禁止运行时手改人物关系绕过规则。 |
| `battle-mid-round-boundary` | 完整回合已提交的战斗存档，验证刷新、自动策略、物品消耗和终态恢复。非完整候选回合不得作为已保存结果。 |
| `breakthrough-outcomes` | 定向 RNG 测试覆盖成功、普通失败与严重失败；使用同一概率计算入口，不靠重复读档抽到指定结果。 |
| `ai-responses` | 合法提议、含糊条款、无效 JSON、未知 ID、越权效果、过期／重复／迟到响应，均为明确标为测试的固定数据。 |
| 语义状态比较 | 按 TDD 规范比较游戏日、实体、位置、资源、RNG、事实、记忆、承诺、故事和行动状态。传输 requestId、日志时间等排除项必须逐项列出；不能笼统排除“不同字段”。 |
| 原子状态比较 | 除语义状态外，还检查 revision、命令去重记录、当前会话、长行动检查点与存档版本，防止世界看似恢复但重复执行保护丢失。 |

以上是待制作夹具的规格，不表示本包已经附带可导入游戏的真实存档。

## 9. 报告模板

开发阶段每个任务至少填一份，不要求为简单样式另造重复测试。

```text
Task: Mx-xx
Status: planned | in_progress | blocked | done
Commit/build:
Environment: OS / browser / device / Node / package manager
Versions: schema / generator / rules / content / assets / RNG
Changed files:

Acceptance:
- AC-xxx | not_run / passed / failed / blocked
  Given:
  When: 实际命令或人工步骤
  Expected:
  Actual:
  Evidence: 报告、截图或测试输出路径

Seed and fixture:
Data/version impact:
Remaining issues:
Unverified devices/providers:
Next task:
```

发布候选阶段应另列严重度：阻断（损档、无法继续、重复资源、越权写入）、主要（关键选择难以理解、状态反馈不一致）、一般（不阻断的排版／内容问题）。不通过删除数据、跳过故障世界或把功能关闭却仍标称支持来解决验收失败。
