# 开发任务清单

版本：V0.1.1-Web。状态：**全部 planned，尚未编码或验收**。本文件把 GDD、TDD 和内容规范转为可领取任务；验收细则见 `ACCEPTANCE.md`。共 34 个任务，编号保留 M0—M10 的推进顺序。


内容协作补充：`CONTENT_PACKS.md` 另列 CP-01—CP-03 共3项 planned 任务及验收，原34项编号保留。CP-01 在 M2-01 前完成；CP-02 在 M5 接入时实施并于 M8-01 前完成；CP-03 在 M10-02 前完成。后续领取任务须同时检查这些补充门槛。

## 1. 执行约定

- 每次领取一个 Task；先读根目录 `AGENTS.md`、对应设计章节和本任务的验收编号。实现文件路径由 TDD 的依赖方向约束。
- 本文的目录和模块名是目标产物，不表示这些文件已经存在。测试结果、构建和截图必须来自实现后的运行。
- 任务状态从 `planned → in_progress → done`；遇到真实阻塞可用 `blocked` 并写原因。只有所引用验收全部达到门槛，任务才能标记 `done`。依赖设备或供应方的验证未做时，不得写“全部通过”。
- 代码提交同时提供：变更文件、对应 AC 实际结果、测试命令与退出码、涉及版本、人工证据和剩余问题。产物可位于 `docs/reports/<task-id>.md`；报告模板见验收文件。
- 配置数值以 GDD 的“原型默认”与 TDD 为准；用户尚未逐项确认的规则不得改写为正式定案。实现时把这些值放入有版本的配置，禁止散落硬编码。
- 一个 Task 可以分多次提交，但不能通过删掉验收、放宽不变量或伪造测试输出来完成。低影响文字和样式用人工检查；随机、存档、承诺、战斗与 AI 写入必须有行为测试。
- M0 的三幕数据仅验证图文交互。M1 才建立并保存 CreationDraft／PlayerProfile，M2 的 FinalizeCreateRun 才将角色接入真实世界；M5 删除夹具路由对正式游戏的依赖。
- 默认本地开发与本地构建；发布、绑定域名、接入真实付费供应方属于具体部署任务，不能在“初始化工程”时顺带执行。

## 2. M0：首批可直接领取任务

### M0-01 工程、依赖与分层基线

**状态：**planned。**前置：**阅读 GDD、TDD、AGENTS；不依赖其他代码任务。

**目标：**得到一个可干净安装、运行和验证的 React + TypeScript + Vite 工程，并用依赖约束保护规则核。

**范围：**

1. 使用当前开发环境可支持的工具版本，记录 Node、包管理器和依赖实际版本；提交唯一锁文件，不写 `latest` 作为项目复现依据。
2. 建立 `src/core`、`application`、`infrastructure`、`worker`、`ui`、`content` 与 `tests`；建立最小 React 入口和真实开发启动命令。
3. 配置 TypeScript strict、类型检查、规则单测、浏览器测试入口、构建和依赖边界检查。脚本名称在 README 和后续任务一致。
4. Git 已存在时复用仓库；未存在时初始化。忽略依赖、构建、测试临时输出、`.env` 和本地密钥；提供不带秘密的配置示例。
5. 建立统一日志接口，默认不记录 APIKey、完整存档或玩家自由输入；开发日志携带 task/request/command 等定位信息。

**产物：**工程配置与锁文件、README 启动步骤、分层空模块、测试入口、日志接口、忽略规则。

**数据／版本：**建立版本常量与版本说明入口；此任务不生成世界、不确定正式美术和玩法数值。

**Given / When / Then：**

- Given 干净检出和 README 指定环境；When 安装依赖并执行类型检查、测试与构建；Then 命令成功且无本地未提交文件依赖。
- Given core 尝试引入 React、DOM、存储或 HTTP 适配；When 执行边界检查；Then 检查失败并定位违规依赖。

**验收：**AC-001、AC-002。

**完成证据：**实际环境版本、命令与退出码、边界违规样例的失败结果、干净检出记录。

### M0-02 三幕图文界面夹具

**状态：**planned。**前置：**M0-01；可与 M0-03、M0-04 并行。

**目标：**让用户在电脑和手机尺寸中完成“坊市相识 → 商定约定 → 重逢”的演示，验证阅读与选择节奏。

**范围：**

1. 三幕夹具绑定固定场景和人物 `assetId`；第三幕提供履约、违约两份预先写好的结果夹具。明确显示“演示数据”。
2. 实现状态栏、图片容器、HTML 正文、2—4 个选项、当前结果、人物档案入口与历史抽屉；历史内按钮不可执行。
3. 分离“当前一幕”和“历史”，图片预留尺寸、提供替代文字；图片失败显示合法占位图。
4. 选项显示已知耗时／消耗，展示处理中、锁定原因和错误重试样式；此阶段只切换夹具，不假装执行领域规则。
5. 提供键盘焦点、触摸按钮和长文本展开；隐藏技术 ID、Seed、事务与调试字段，调试页另设入口。

**产物：**可访问的演示路由、三幕夹具、图文组件、临时资源清单、桌面与手机截图。

**数据／版本：**夹具独立于正式存档与 RNG；无玩法状态迁移。

**Given / When / Then：**

- Given 390 CSS px 手机宽度和桌面宽度；When 点击完成三幕、打开档案再返回；Then 正文完整可读、行动可触达、当前幕未丢失。
- Given 场景图返回失败；When 阅读并选择；Then 文本、人物身份与按钮仍可用，页面不会再执行一次行动。

**验收：**AC-003、AC-004。

**完成证据：**桌面／手机视口截图、人工走查记录、图片失败演示。没有真实 iPhone 时只报告视口模拟。

### M0-03 Worker 命令管线与候选状态

**状态：**planned。**前置：**M0-01；M0-05 将接入事务。

**目标：**建立 UI 到 Worker 的唯一写入口，确保一次只计算一个修改世界的命令。

**范围：**

1. 按 TDD 定义 commandId、saveId、expectedRevision、命令类型、负载和结果／错误消息；跨边界执行运行时校验。
2. Worker 接受命令、排队、以已提交状态计算候选状态；规则核不可修改输入。使用最小测试状态即可，无需 NPC 或完整世界。
3. application 暴露持久化端口；候选状态只能在端口确认完整提交后替换已提交状态并返回成功。未接真实 IDB 时以可控测试适配器覆盖成功和拒绝。
4. 区分进度、候选计算结束、提交成功、提交失败四种消息；进度不作为成功回执。主线程只显示当前已提交视图和非权威进度。
5. 提供 Worker 初始化失败、未知消息、重复 message 和拒绝错误的可恢复界面；React 重挂载不自动发领域命令。

**产物：**消息协议、Worker 宿主、串行命令队列、application 持久化端口、最小状态行为测试。

**数据／版本：**建立协议版本和运行时校验；后续扩展命令保持明示版本策略。

**Given / When / Then：**

- Given 两个紧邻的修改命令；When 同时发送；Then Worker 顺序处理并依据每次提交后的状态验证下一个命令。
- Given 计算已完成但持久化未成功；When UI 查询当前状态；Then 得到旧的完整状态，没有提前展示成功或消费后资源。

**验收：**AC-005、AC-006。

**完成证据：**可控提交测试的消息轨迹、失败前后状态差异、协议拒绝用例。

### M0-04 时钟、随机流、稳定 ID 与事实接口

**状态：**planned。**前置：**M0-01。

**目标：**让同一输入与同一版本的规则结果可重现，并为世界生成、事件与调度提供统一基础接口。

**范围：**

1. 使用整数游戏日，提供显式推进接口；core 禁止直接读取现实时间或调用全局随机。
2. 按 TDD 固定 RNG 算法和状态序列化，划分角色重掷、世界生成、模拟、战斗和叙事随机流；提供保存／恢复。
3. 建立稳定实体 ID、事件 ID 和事实事件的最小格式。传输 commandId 与领域稳定 ID 分开；定义语义状态指纹排除哪些传输元数据。
4. 实现 canonical 序列化／语义指纹所需的稳定字段排序与数值约定；规则版本、生成器版本、内容版本进入测试报告。
5. 提供固定随机序列测试向量和可复用的“相同输入→相同结果”断言；暂不生成实际世界。

**产物：**时钟、RNG、ID 与事件接口；测试向量；版本与指纹范围说明。

**数据／版本：**RNG 算法和版本属于存档兼容内容；改变时不得静默按新算法续跑旧存档。

**Given / When / Then：**

- Given 一个随机流已取出前 n 项并保存；When 恢复并继续；Then 后续序列与未中断序列一致。
- Given 世界流状态未变；When 单独执行 100 次角色重掷或多次渲染；Then 世界流输出保持一致。

**验收：**AC-007、AC-008。

**完成证据：**测试向量、恢复对比、流隔离结果、语义指纹定义。

### M0-05 IndexedDB 原子存档与 JSON 备份

**状态：**planned。**前置：**M0-03、M0-04。

**目标：**把最小状态的命令处理变为可刷新、可去重、可拒绝冲突的可靠存档闭环。

**范围：**

1. 实现 SaveRepository；在同一个 IDB 读写事务中读取当前 revision 和 commandId 记录，校验后写入状态、随机状态、事件、会话、命令记录及新 revision。
2. 仅以 transaction complete 作为成功；单项 request success 不发送 ack。不把计算、网络等待或图片请求放在存储事务中。
3. 同 commandId 且同负载返回已有结果；同 ID 不同负载拒绝；expectedRevision 过期拒绝并要求重载，不覆盖其他标签提交。
4. 提供同一存档主写页面提示；即使提示或页面锁失效，IDB 事务内 revision 校验仍必须挡住并发覆盖。
5. JSON 导出完整可恢复存档；导入先进行大小、结构、版本、引用和范围校验，在副本／新存档槽验证，成功后再允许切换。拒绝可执行内容、密钥字段和未知未来版本。
6. 模拟存储配额失败、事务中止和损坏导入，旧存档保持可读；处理 versionchange 与 blocked，迁移失败不重置世界。

**产物：**IDB 适配器、导入导出界面、迁移入口、故障注入集成测试、跨标签测试。

**数据／版本：**数据库版本与存档格式版本分开；最小正式 envelope 从此阶段起沿用，后续增加玩法字段时按迁移策略处理。

**Given / When / Then：**

- Given 候选状态已算出但事务随后中止；When 重开页面；Then 仅恢复上一次完整存档，资源、时间、事件和命令记录无半写入。
- Given 两标签基于同 revision 发出不同命令；When 竞争提交；Then 最多一个提交成功，另一个明确收到冲突。
- Given 一份有效导出；When 导入新槽并打开；Then 语义状态一致；导入失败时原槽不变。

**验收：**AC-009、AC-010、AC-011、AC-012。

**完成证据：**事务故障前后导出对比、跨标签浏览器记录、JSON 往返与损坏输入结果、升级 blocked 操作记录。

## 4. 阶段关口与交付范围

| 关口 | 允许开始下一阶段的证据 | 不满足时的行动 |
| --- | --- | --- |
| M0 → M1 | AC-001—AC-013；图文夹具可读可点，最小存档原子提交与故障恢复成立 | 修工程／交互／存储，不扩大内容 |
| M2 → M3 | 40 NPC 初始世界确定性与恢复结果成立 | 固定生成与版本差异，避免在坏世界上堆行为 |
| M3 → M4 | 固定回归集 100 NPC × 3650 日零不变量错误、检查点续跑一致 | 使用输出的 Seed／日／事件重放失败，不跳过出错实体 |
| M5 → M6 | 真事件引用真实在场人物、刷新无重抽、可正常离开 | 修事件资格与会话持久化 |
| M8 → M9 | 固定选项完整故事可玩，履约／违约真实改变后续行为 | 先修人物故事，AI 不承担修复状态机的责任 |

本清单不承诺开发工期；34 个 Task 的规模是拆解单元，不是 34 天。新增金丹、更多地图、云同步、完整 Mod 编辑器、多人和实时生图需要另立任务，不自动扩入当前任务。
