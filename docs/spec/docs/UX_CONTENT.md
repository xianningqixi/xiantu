# 图文交互与首条人物故事规格

版本：V0.1.1；状态：可交给开发的设计规格和内容样例，尚未实现页面或通过游玩验收。数值以 `content/prototype-balance.json` 为准；本文件不另建一套平衡表。`content/storylets.json` 含 14 个节点，`content/assets.json` 含 8 个待制作资源记录；目前没有成品图片。

## 1. 页面结构与路由

主要体验为「一幕画面＋一段正文＋当前行动」。固定事件选项应能独立走完整条人物故事。单幕在手机上优先显示当前内容，历史放到独立入口；开关面板和读完文本不自动推进日期。

| 路由建议 | 主要内容 | 权威状态与恢复原则 |
| --- | --- | --- |
| `/` | 新游戏、继续、导入存档 | 只列有效存档；不生成新世界 |
| `/create` | 姓名、性别、外貌、资质重掷、法宝、模式 | 未确认前为创角草稿；确认通过命令建立存档 |
| `/game/:saveId` | 当前地点、在场人物、当前一幕、常规行动 | 入口读取已提交世界与活动会话；不按路由参数任意选择剧情 |
| `/game/:saveId/character/:entityId` | 人物资料、可知共同经历与当前承诺 | 只读；未知私事不显示；亡者可看历史资料 |
| `/game/:saveId/expedition` | 当前探索节点、队伍、遭遇、返回条件 | 必须已有活动探索；战斗/掉落由核心控制器管理 |
| `/game/:saveId/battle` | 当前完整回合、手动/自动、合法行动、战报 | 读取保存的战斗；刷新不重新开始遭遇 |
| `/game/:saveId/journal` | 已发生事件与当时显示的文字、图片引用 | 历史全只读，不携带可再次执行的按钮 |
| `/game/:saveId/settings` | 字体、动效、存档导入导出、AI 设置入口 | 设置不推进世界；敏感设置按 TDD 处理 |

路由仅组织界面，不是剧情或世界权威。打开不存在的战斗、过期人物会话、另一局的实体地址时，回到当前有效页面并说明原因。浏览器后退打开旧页面后，只显示当时记录或重新读取当前状态，不能把旧选项恢复为可执行。

桌面采用主叙事区与人物/状态栏；手机单列、操作区跟随正文。场景图预留固定比例，人物图保留脸和服装识别点，图片加载不推挤按钮。正文为可选择文字；操作是真实按钮；消耗、时长、风险、锁定原因同时适用于键盘和触摸。长文展开、档案抽屉、返回键均保持焦点与阅读位置。图片替代文字直接来自素材记录。

## 2. 行动状态矩阵

| 状态 | 画面与提示 | 可以做什么 | 不能做什么 |
| --- | --- | --- | --- |
| `idle` | 当前已保存版本的一幕与可用选项 | 查看、选项预览、提交合法行动 | 将浏览当成行动 |
| `submitting` | 保留旧的已提交画面；显示正在结算/保存的状态 | 读已有内容；长行动按协议暂停计算 | 重复提交同一选择，提前播放领取/突破成功结果 |
| `saved` | 新修订号的结果、消耗与后续行动；短暂提示已保存 | 继续新的行动 | 因图片或动画未结束而再次结算 |
| `error` | 保留最后完整状态；说明本次未确认完成 | 查询命令状态、使用同一个命令 ID 重试、导出可用旧存档 | 直接新建 ID 重做可能已成功的扣款/掉落 |
| `stale` | 说明世界已变化或另一标签页已写入 | 重新读取当前状态并生成有效选项 | 继续执行旧 NPC、旧约定或旧价格的选项 |

`error` 不等于一定没执行：响应丢失时先查询同一命令 ID，确认已提交则显示原结果；只有已明确回滚才能从原状态重新预览。持久化失败不显示成功文案。`saved` 的来源是完整事务完成通知，不能用图片加载、动画结束或单次字段写入替代。

图片请求的状态与上述命令状态独立。待制作、404、超时、解码失败都使用同尺寸 CSS 占位、替代文字和人物名字，行动继续可用；图片完成后仅替换视觉元素。AI 失败也保持固定选项可用。返回历史页时明确标记「历史记录」，不显示活跃动作按钮。

## 3. 每个选项的执行约定

`choices` 全部包含 `id`、`label`、`commandType`、`args` 与 `conditions`。空条件显式写作 `[]`，无参数显式写作 `{}`。会话保存展示时的选项和世界修订号；最终提交携带新生成但重试不改变的命令 ID、期望修订号及源会话/选项 ID。

`nextStoryletId` 是执行完成后的候选导航提示。系统仍然重新检查参与者、地点、时间、剧情条件与 `once`；候选不成立时回当前地点或活动控制器，不瞬移、不召回 NPC、不跳过三日等待。例如在客栈完成突破并不直接进入坊市重逢，需要玩家实际旅行到坊市。

| 类型 | 交互行为 | 世界后果 |
| --- | --- | --- |
| `OpenProfile` | UI 只读动作，打开角色或约定面板 | 不发领域命令，不推进时间，不消耗 `once` |
| `LeaveInteraction` | 关闭当前文字会话或返回已有探索界面 | 可持久化会话关闭状态，不结束探索、不移动、不发奖 |
| `AdvanceDialogue` | 确认读完结果并保存会话进度 | 不增关系/物品、不推进天数；可将已结束节点标为完成 |
| `Talk` | 仅允许白名单话题 | 初识、一次性功法、目标获知、重逢记忆由固定处理器产生；普通重复交谈没有数值奖励 |
| `ProposeAgreement` | 展示规则生成的完整草案 | 建草案，不扣钱、不组队、不转移物品 |
| `AcceptAgreement` | 玩家最终确认、NPC 意愿复核 | 记录accepted同意条款，不冻结NPC日常，不扣出征报酬 |
| `FormParty` | 检查人数、境界、伤势、意愿与占用 | 建队并保持共同位置，实际行动时才占用，不扣出征报酬 |
| `StartExpedition` | 显示费用、同行者和耗时，明确确认后提交 | 开始一次持久行动，原子支付双方出征报酬并锁定同行；山门到遗迹这一日包含在行动内 |
| `Travel` | 显示相邻路线耗时与队伍状态 | 按固定路线旅行，同步同行者；返程显式遗迹→坊门→坊市 |
| `StartTraining` / `StartBreakthrough` | 预览实际资格、消耗、概率和代价后确认 | 复用共用修炼规则；突破失败仍非致命 |
| `AllocateLoot` | 展示待分配池、原约定与实际分法 | 唯一结算入口；同步库存、承诺、关系、记忆与行程状态 |

故事 JSON 中的按钮定义不能直接写入任意 effect 或 stat。`Talk` 话题白名单为 `LIN_FIRST_MEETING`、`CLAIM_BEGINNER_MANUAL`、`LIN_COMMON_GOAL`、`LIN_REUNION_FULFILLED`、`LIN_REUNION_BREACHED`。每个处理器必须核对源会话、对象和真实事实；不能把 `topicId` 解释为可执行脚本。

规则效果的映射由共用规则表负责：`EFFECT_FIRST_MEETING` 对应初识事实，`EFFECT_FULFILL` 对应实际履约结算，`EFFECT_BREACH` 对应实际违约结算。正文不产生这些效果，事件回放和重逢对白也不重复应用。功法通过终身 `claimId = starter-manual` 发一次并学习；客栈备用入口使用相同 claim。重逢可以登记一次 NPC 已表达的记忆，不再次套用履约/违约的数值效果。

违约按钮先打开结算对照与二次确认，说明「草也归自己、该约定记为违约、信任变化和后续邀请限制」；取消不提交。确认的资源与变化来自同一次预览和修订号，最终仍由领域校验。展示精确关系数值与否由 UI 配置决定，但已知违约性质不能隐藏。

## 4. 条件 DSL 与事实投影

所有条件使用扁平对象 `{kind, subjectId, key, op, value}`，顶层 `conditions` 与选项 `conditions` 各自为 AND，不嵌任意表达式。运算仅接受契约列出的操作：`eq`、`ne`、`gte`、`in`、`contains`。`in` 的右值是同类型枚举数组，`contains` 用于成员 ID 数组并接收一个 ID，不做子串匹配。缺实体、缺 key、类型不匹配均不满足，不使用 JavaScript 隐式类型转换。

`value: {ruleRef: "story.reunionWaitDays"}` 只能解析当前锁定规则版本中的白名单常量路径；不存在或类型错误则内容校验失败，不把任意字符串当字段读取路径。主体 `STORY_LIN_WAN_01` 映射该故事已经绑定的约定、队伍、探索和结算记录。首次结算后该故事的 agreementId、expeditionId 与 settlementDay 保留，不被后续普通探索覆盖；新的探索使用自己的 scope 和实例 ID。`PLAYER` 映射本局主角，不是可切换的浏览器身份。

| kind | key | subjectId | 类型、定义和来源 |
| --- | --- | --- | --- |
| `entity` | `alive` | 角色 ID | boolean，由角色存活状态投影 |
| `entity` | `locationId` | 角色 ID | 稳定地点 ID；同屏交谈要求双方在场且存活 |
| `entity` | `realmTier` | 角色 ID | integer：凡人 0、炼气 1、筑基 2；小层不混在此字段 |
| `fact` | `lin.firstMeetingRecorded` | 故事 scope | 是否已提交初识事实；初始 false |
| `fact` | `lin.manualClaimed` | 故事 scope | 终身 starter-manual claim 已完成且入门法已学习；历史命名虽带 lin，客栈保底同样为 true，不据此虚构见过林晚 |
| `fact` | `lin.goalKnown` | 故事 scope | 玩家是否通过有效对话得知本次共同目标；不读取 NPC 全部隐藏目标 |
| `fact` | `lin.storySettlementResult` | 故事 scope | 当前故事探索结算结果：`fulfilled` / `breached` / `not_triggered` / `impossible` / `cancelled`；未结算时缺值 |
| `fact` | `lin.reunionRecorded` | 故事 scope | 对应结算分支的重逢话题是否已提交；未记录 false |
| `fact` | `player.canBreakthroughToQi` | 故事 scope | 共用资格函数对当前玩家凡→炼气的只读结果，不能在内容层复制概率或修为阈值 |
| `agreement` | `status` | 故事 scope | `none` / `draft` / `accepted` / `active` / `fulfilled` / `breached` / `not_triggered` / `impossible` / `cancelled`；无绑定约定时明确投影 none |
| `party` | `memberCount` | 故事 scope | 绑定当前队伍活跃成员数；未组队时玩家视作单人队，值 1 |
| `party` | `memberIds` | 故事 scope | 对应当前活跃成员数组；已死亡/正式离队者不能算有效队员 |
| `expedition` | `phase` | 故事 scope | `none` / `ready` / `active` / `resolved` / `settled`；ready 表示组队及约定准备完成且尚未出征，资源仍须出征时复核 |
| `expedition` | `hasPromisedGrass` | 故事 scope | 本次实际获得且尚待分配的首株凝元草存在；不包含玩家已有背包物品 |
| `expedition` | `settlementReady` | 故事 scope | 探索已结束、玩家已返坊市、该行程未结算且可按有效条款结清；即使零掉落也可为 true |
| `expedition` | `exceptionSettlementRequired` | 故事 scope | 无草、受益人死亡、合法取消等需要专门处理的结算，而不是普通履约/有意违约路径 |
| `clock` | `daysSinceStorySettlement` | 故事 scope | 当前游戏日减去该探索已提交 settlementDay；尚未结算时不满足任何比较，不能默认为 0 |

条件只决定故事/选项是否候选。命令最终还检查资源、伤势、参与者、NPC 同意、队伍占用、承诺冲突与修订号，UI 将这些领域拒绝原因转成清楚的锁定说明。开页面不应为了满足条件而改变状态。

`once=true` 表示该故事 scope 内该节点完成后不再作为新事件入选。完成由白名单 Talk 的剧情推进事实或确认结果的 AdvanceDialogue 标记；仅展示、OpenProfile、LeaveInteraction、Travel 不消耗关键剧情资格。`once=false` 的修炼、条款和地点节点允许重入，是否能发功法、扣钱、结算仍由命令的一次性标记约束。`cooldownDays` 根据最后成功完成的游戏日检查；样例为 0，非关系刷取计时器。重逢另外使用明确结算日与配置天数。

## 5. 14 节点走法

| ID | 进入条件和用途 | 正常出口 |
| --- | --- | --- |
| `STORY_MARKET_FIRST_MEETING` | 坊市见到活着的林晚；没有初识事实 | Talk 认识→功法说明 |
| `STORY_MARKET_MANUAL` | 认识林晚后，同地点对话 | 一次领取并学习；前往客栈 |
| `STORY_INN_TRAINING` | 客栈、已学功法 | 修炼、凡→炼气突破、返回坊市；可重复且不能自动突破成功 |
| `STORY_MARKET_GOAL` | 至少炼气，林晚、周安实际同在坊市 | 明确共同目标 |
| `STORY_MARKET_TERMS` | 已知目标，三方在场 | 提出 draft→复核并接受 |
| `STORY_MARKET_AGREED` | 已接受条款但未出征 | 正式组队→全队旅行至坊门 |
| `STORY_GATE_PREPARATION` | 坊门的可复用节点 | 条件满足开始探索；或返回坊市；返程也经过本节点 |
| `STORY_RUINS_EXPEDITION` | 活动或刚结束的实际探索 | 去探索控制器完成遭遇；结束后返回坊门 |
| `STORY_MARKET_LOOT` | 已回坊市且未结算 | 实际履约、有意违约、条件未触发/不能履行 |
| `STORY_MARKET_FULFILLED` | 已提交履约；林晚仍活着且同在坊市 | 看结果、继续日常活动 |
| `STORY_MARKET_BREACHED` | 已提交违约；林晚仍活着且同在坊市 | 看结果、继续日常活动 |
| `STORY_MARKET_UNTRIGGERED` | 该行程已按异常条款结清 | 说明原因、继续日常；不冒充履约/违约 |
| `STORY_MARKET_REUNION_FULFILLED` | 结算至少经过配置天数，林晚活着在场 | 引用实际赠草经历、登记重逢；普通邀请规则已受履约影响 |
| `STORY_MARKET_REUNION_BREACHED` | 同上，结算是违约 | 引用实际违约经历、登记重逢；原条件再邀会受规则限制 |

探索层负责具体遭遇、技能、撤退、胜负与掉落，内容节点不另写一套战斗。`LeaveInteraction {destinationView: "active-expedition"}` 只是显示已存在的探索控制器，不能让玩家免费结束战斗或获得战利品。

临时原型的分配约定固定为：这一次探索的第一株凝元草给林晚，其余所有物品和灵石归玩家；多出的凝元草也归玩家。两名 NPC 各固定 1 灵石出征报酬，数值来自 `story.departureFeePerNpc`，仅在 StartExpedition 接受时各支付一次。提议、接受、组队、读档、回来分配均不二次扣付。获得次序使用掉落事实的稳定事件序号及物品单元序号，不使用背包展示排序。

未获得草时，该赠草义务为 `not_triggered`，不是玩家违约；正常撤退不退已经支付的出征服务费。取得草之后故意留给自己才走违约路径。受益人死亡等按 TDD 的 `impossible` 处理，保留原约定及原因，不把草转给死人，也不把主动侵占伪装成无法履行。无掉落仍要提交一次空池结算，关闭本次义务。

回坊市前战利品池不可出售、使用、赠送或放进玩家私人仓库；退出页面不绕过分配。无法当面显示结果时，展示事实结算摘要，人物对白候选等待在场条件。库存和关系结果已经提交，不为再次见面重做结算。NPC 对玩家隐瞒的事实也不会凭内容节点自动全知。

## 6. 保底行动、重逢与真实世界兼容

| 常规入口 | 用途 | 约束 |
| --- | --- | --- |
| 客栈 `ClaimStarterManual` | 林晚离开或死亡时仍能免费领取学习入门功法 | `sourceLocationId=LOC_INN`，与 Talk 共用 starter-manual 终身 claim；不写初识林晚事实 |
| 坊市/客栈/坊门的劳务 | 缺钱后仍可获得出征、准备资源 | 按 balance 的无风险劳务命令与耗时，不依赖故事进度 |
| 客栈修炼、休息及等待 | 成长、伤势恢复、让世界自然过日 | 显示耗时与期间熟人动态；关掉网页不补算现实天数 |
| 可用地点旅行 | 离开、返程、寻找实际在场人物 | 坊市↔客栈 0 日；坊市↔坊门 1 日；坊门↔遗迹 1 日，按 balance 路线表 |
| 人物页的邀请与承诺 | 看到履约对未来意愿的实际影响 | 调用共用邀请规则；不能靠第二次播放重逢绕过违约限制 |
| 条件允许的补偿入口 | 玩家日后补偿违约 | 属于新的资源/补偿事件，保留原违约记录；本轮 14 节点不另外扩成长篇支线 |

首条故事的两名重点 NPC 以坊市为生活据点，按 balance 设定定期回坊市购药、交易、整理行装，同行或护法占用期间不执行冲突行程。玩家在客栈修炼/等待后可以正常返回坊市查看在场名单；不需要现实计时，也不靠历史事件按钮召唤 NPC。

重逢日以本次行程结算日为基准，不以退出对白、刷新网页或看到结果的时间为准。例：结算后尚未过三日，即使反复回坊市也不提前触发；过了三日但林晚不在，继续正常生活与寻访即可。具体等待采用 `story.reunionWaitDays`，当前配置为三日。

NPC 仍使用同一修炼规则。林晚可能在玩家闭关期间突破，她的台词应根据可知状态说「下一段修炼/巩固所需」，不能继续假称尚未筑基。已经接受的赠草约定不会只因她境界变化消失。她死亡时不再出现当面对话或活人重逢，历史页仍可引用她；玩家的修炼和筑基流程继续有效。

## 7. 素材制作范围

首批仅列坊市、客栈、坊门、遗迹四张场景背景；林晚平静/缓和/戒备三种表情，以及周安一张固定立绘。全部资源 `status=planned`、`filePath=null`，来源与使用权 `pending`。这是制作清单，不是已经存在的图片。

背景继续保留古风像素方向，人物使用精细非像素古风立绘；是否统一成非像素背景，等样例比较再定。人物身份绑定 actor ID 与版本，表情变换不能改变发型、五官、服饰主特征；不为刷新或第二次相见重新随机脸。没有资源时用有角色名字的稳定占位，不把周安的整张脸复用成林晚。

正式资源接入时必须填真实文件、尺寸与来源，在实际手机上检查裁切。素材版本与内容版本锁定；历史引用资源 ID，缺旧图时显示文字和占位而不是悄悄改写过去。每次图文交互可复用背景与人物图；实时生图不作为关键路径依赖。

## 8. 可执行验收分支

以下是待开发后执行的验收规格，不是已通过的测试。实现方应同时保留命令记录、预期事实断言与关键页面截图，避免只测文案是否出现。

| Case | 设置与操作 | 必须断言 |
| --- | --- | --- |
| UX-01 正常履约 | 固定测试世界→功法→炼气→三人探索胜利→返坊分配→过等待日再见 | 首株归林晚、余物归玩家、报酬各一次；履约关系只生效一次，重逢引用正确事实 |
